## Description

Simulated order matching engine for paper trading. Processes incoming ticks against pending orders, generates fills with slippage and fee deductions.

## Requirements

- Define `struct MatchingEngine`:
  - `fee_schedule: FeeSchedule`
  - `slippage_model: SlippageModel`
  - `next_fill_id: u64` (monotonic counter)
- Implement `fn new(fee_schedule: FeeSchedule, slippage_model: SlippageModel) -> Self`
- Implement `fn process_tick(&mut self, tick: &Tick, pending_orders: &mut Vec<Order>) -> Vec<OrderFill>`:
  - For each **Market** order: fill immediately at `tick.price` + slippage, compute fee, generate `OrderFill`, set order status to `Filled`
  - For each **Limit Buy** order: fill if `tick.price <= order.price` (price crosses limit), execute at order's limit price + slippage
  - For each **Limit Sell** order: fill if `tick.price >= order.price`
  - Update `order.filled_quantity` and `order.status` (`Filled` or `PartiallyFilled`)
  - Remove fully filled orders from the pending list
- Implement `fn submit_order(&self, order: &Order) -> Result<(), EngineError>`:
  - Validate: quantity > 0, price >= 0 for limits
  - Return `EngineError::InvalidOrderSize` on failure

## Acceptance Criteria

- [x] Market buy order is filled at tick price + slippage
- [x] Market sell order is filled at tick price - slippage
- [x] Limit buy order triggers when tick price ≤ limit price
- [x] Limit sell order triggers when tick price ≥ limit price
- [x] Fee is correctly deducted from each fill
- [x] Order status transitions to `Filled` after full execution
- [x] Zero-quantity order is rejected with `InvalidOrderSize`
