## Description

Recursive descent parser that converts a token stream into an Abstract Syntax Tree (AST). Handles operator precedence and nested expressions.

## Requirements

- Implement `fn parse(tokens: &[Token]) -> Result<Vec<Stmt>, ScriptError>`:
  - Parse top-level statements: assignments, if/else blocks, signal statements, expressions
- Operator precedence (lowest to highest):
  1. `||` (logical OR)
  2. `&&` (logical AND)
  3. `==`, `!=` (equality)
  4. `<`, `>`, `<=`, `>=` (comparison)
  5. `+`, `-` (addition/subtraction)
  6. `*`, `/` (multiplication/division)
  7. Unary `-` (negation)
  8. Function calls, parenthesized expressions, literals
- Parse `if condition { stmts } else { stmts }` — else block is optional
- Parse `buy()` and `sell()` as `Stmt::SignalBuy` / `Stmt::SignalSell`
- Parse `name = expr;` as `Stmt::Assign`
- Parse `func(arg1, arg2)` as `Expr::FunctionCall`
- Return `ScriptError::ParseError` on unexpected tokens

## Acceptance Criteria

- [x] `parse("x = sma(20);")` produces `Stmt::Assign` with `FunctionCall`
- [x] `parse("if rsi(14) < 30 { buy() }")` produces correct `Stmt::If` with `SignalBuy`
- [x] `parse("a + b * c")` respects precedence: `Add(a, Mul(b, c))`
- [x] `parse("if x > 0 { buy() } else { sell() }")` parses both branches
- [x] Missing closing brace returns `ParseError`
- [x] Unexpected token returns `ParseError` with token index
- [x] File stays under 250 lines
